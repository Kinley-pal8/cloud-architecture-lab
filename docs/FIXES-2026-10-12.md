## 1. EKS architecture reference was missing its workload node

**File:** `src/data/references/15-eks-architecture.json`

**Problem.** The reference added in `a49c031` had no `eks-workload` node, yet three things
depended on it:

- the request scenario (`startNodeId: "eks-workload"`);
- the reference description ("Start Send Request at Application Service…");
- `test/eks-reference.test.ts`, which edits that node's `readyPods`, `serviceSelector` and
  `controlPlaneAvailable`.

**Effects.**

- `parseReference` rejected the file ("Invalid reference request scenario"), so
  `test/eks-reference.test.ts` crashed on load and the "every built-in reference loads" check in
  `test/reference-library.test.ts` failed. CI (`.github/workflows/verify.yml`) was red.
- In the app nothing crashed, but `requestSimulator` silently fell back to another start node
  (the admin user). Because every edge in this diagram is a non-traversable management
  illustration, the lesson this reference exists for could not be simulated: Service readiness
  (zero Ready pods or a selector mismatch → 503).

**Fix.** Added the `eks-workload` node ("Application Service · 3 Ready pods") in private subnet 2.
It copies the existing `alpha-eks-workload` node from `16-eks-multi-cluster-architecture.json`,
with the cluster name changed to `eks-architecture` and the 3 Ready pods matching the three pods
drawn in this diagram. The node sits in an empty area of the subnet, so no other node or
boundary moved. One mis-indented line in the JSON was also normalised.

**Verified by:** `test/eks-reference.test.ts` (5 tests, including the success / 503 / 400
readiness cases) and `test/reference-library.test.ts`.

## 3. Smaller production bundle

**File:** `vite.config.ts`

**Problem.** `src/components/icons/awsIconRegistry.ts` imports all 307 service SVGs eagerly. By
default Vite inlines any asset under 4 kB as base64 into the JavaScript, so most icons were
embedded in the main bundle (base64 adds about 33% to their size).

**Fix.**

- `build.assetsInlineLimit` excludes `src/components/serviceIcon/` icons, so each one is emitted
  as a separate cached file and fetched only when displayed. Other assets keep Vite's default.
- `manualChunks` splits React, `@xyflow/react` and `lucide-react` (and other dependencies) into
  separate long-cached chunks.

**Still open.** The main chunk (1.1 MB) is still above Vite's 500 kB warning. The rest is
engine, data and UI, all loaded via `ArchitectureProvider`, which also wraps the home page.
Further reduction needs the lab to be lazy-loaded; that changes how state is shared between home
and lab, so it was left out of this fix.
